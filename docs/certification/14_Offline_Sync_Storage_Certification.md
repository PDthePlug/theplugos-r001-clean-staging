## 1. Local-First Event Storage Architecture

ThePlugOS strictly enforces a **Local-First, Cloud-Second** data lifecycle. All operational events generated by cashiers, kitchen staff, and managers are written to local durable storage (IndexedDB/SQLite) before any network transmission occurs.

```
[User Action] ──► [Local Event Ledger] ──► [CQRS State Projection] ──► [UI Updated (0ms)]
                           │
                           ▼
                  [Local Durable Outbox]
                           │
           ┌───────────────┴───────────────┐
           ▼                               ▼
 [Local Peer Mesh Sync]          [Cloud Sync Adapter]
  (Wi-Fi LAN - Immediate)         (Flushed when Online)
```

## 2. Synchronization Mechanisms

1. **Outbox Pattern:** Operational events are appended to a persistent outbox table.
2. **Inbox Pattern & Idempotency:** Receiving nodes check event IDs against a local deduplication set before applying state transitions. Duplicate packets caused by network retries are safely ignored.
3. **Conflict Resolution Strategy:**
   - **Order Records:** Last-Write-Wins (LWW) based on vector timestamps and sequence offsets.
   - **Inventory Decrements:** Commutative Delta Merging ensures stock levels remain exact across offline devices.
4. **Cloud Reconnection Catch-Up:** When Internet returns, the Outbox automatically flushes accumulated events in topological sequence order, updates checkpoints, and downloads cloud updates.
